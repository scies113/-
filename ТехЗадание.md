### 1. Общие сведения и контекст
* **Дисциплина:** Технологии разработки приложений на базе фреймворков.
* **Тема проекта:** «Система учета домашних заготовок (продукт, заготовка, дата, количество)».
* **Целевое состояние репозитория:** Этап завершения **Практической работы № 3** (полная объектно-ориентированная модель предметной области, развитая из функционального прототипа ПР1 и модульной структуры ПР2).
* **Стек технологий:** Python 3.10+, стандартная библиотека (`json`, `datetime`, `pathlib`, `typing`), инструменты проверки качества: `flake8 >= 7.0`, `pytest >= 8.0`.

#### Назначение модулей и каталогов:
1. **`main.py`**: Точка входа в приложение, организация интерактивного консольного меню (цикл `while`), координация пользовательских сценариев.
2. **`models/`**: Пакет классов предметной области (ООП-модель):
   * `products.py` — класс `Product` (сырьё/основной ингредиент) и вспомогательные функции для коллекции продуктов;
   * `preserves.py` — класс `Preserve` (рецепт/вид заготовки) и функции коллекции заготовок;
   * `batches.py` — класс `Batch` (партия заготовки с датой и количеством) и функции коллекции партий;
   * `__init__.py` — реэкспорт классов: `from .products import Product`, `from .preserves import Preserve`, `from .batches import Batch`.
3. **`storage.py`**: Изолированный слой персистентности. Отвечает за сериализацию объектов в JSON и десериализацию JSON в связанные графы объектов с использованием контекстных менеджеров `with open(...)` и безопасной обработкой исключений (`FileNotFoundError`, `json.JSONDecodeError`).
4. **`utils.py`**: Функции безопасного пользовательского ввода с повтором запроса при ошибке (`input_int`, `input_date`, `input_str`).
5. **`data/`**: Каталог хранения файлов данных в формате JSON.
6. **`tests/`**: Каталог автоматизированных модульных тестов `pytest`.
7. **`requirements.txt`**: Список зависимостей среды разработки (`flake8>=7.0`, `pytest>=8.0`).
8. **`.gitignore`**: Исключение виртуального окружения (`venv/`, `.venv/`), кэшей Python (`__pycache__/`, `*.pyc`), кэша тестов (`.pytest_cache/`).
9. **`README.md`**: Полная сопроводительная документация по шаблону ПР1–ПР3.

### 3. Объектная модель предметной области (`models/`)

В соответствии с требованиями ПР3 сущности предметной области должны быть реализованы в виде классов, поддерживающих строковое представление `__str__`, инкапсуляцию валидации и фабричные методы восстановления из словаря (`@classmethod`).

#### 3.1. Класс `Product` (`models/products.py`)
Описывает базовое сырьё/ингредиент (например: "Огурцы", "Клубника", "Томаты", "Яблоки").
* **Атрибуты объекта:**
  * `id: int` — уникальный идентификатор;
  * `name: str` — наименование продукта;
  * `category: str` — категория (овощи, фрукты, ягоды, грибы и др.).
* **Методы:**
  * `__init__(self, product_id: int, name: str, category: str) -> None`
  * `__str__(self) -> str` — формат: `[#1] Огурцы (Категория: овощи)`
  * `@staticmethod validate_name(name: str) -> bool` — проверка на непустую строку длиной не менее 2 символов.
  * `@classmethod from_data(cls, data: dict) -> "Product"` — сборка объекта из словаря JSON.
  * `to_dict(self) -> dict` — сериализация объекта в словарь для сохранения.
* **Функции модуля `products.py`:**
  * `add_product(products: list[Product], name: str, category: str) -> Product`
  * `find_product_by_id(products: list[Product], product_id: int) -> Product | None`
  * `find_products_by_name(products: list[Product], query: str) -> list[Product]`
  * `show_products(products: list[Product]) -> None`

#### 3.2. Класс `Preserve` (`models/preserves.py`)
Описывает вид/рецепт заготовки (например: "Маринованные огурцы", "Клубничное варенье"). Содержит ссылку на объект `Product` (композиция/агрегация).
* **Атрибуты объекта:**
  * `id: int` — уникальный идентификатор заготовки;
  * `name: str` — название заготовки;
  * `product: Product` — ссылка на объект сырья/продукта (строго экземпляр `Product`, а не просто int ID);
  * `recipe_notes: str` — примечания к рецепту или условия хранения.
* **Методы:**
  * `__init__(self, preserve_id: int, name: str, product: Product, recipe_notes: str = "") -> None`
  * `__str__(self) -> str` — формат: `[#1] Заготовка: 'Маринованные огурцы' (Основной продукт: Огурцы)`
  * `@classmethod from_data(cls, data: dict, product: Product) -> "Preserve"`
  * `to_dict(self) -> dict` — словарь с внешним ключом `"product_id": self.product.id`.
* **Функции модуля `preserves.py`:**
  * `add_preserve(preserves: list[Preserve], name: str, product: Product, notes: str) -> Preserve`
  * `find_preserve_by_id(preserves: list[Preserve], preserve_id: int) -> Preserve | None`
  * `filter_preserves_by_product(preserves: list[Preserve], product_id: int) -> list[Preserve]`
  * `show_preserves(preserves: list[Preserve]) -> None`

#### 3.3. Класс `Batch` (`models/batches.py`)
Описывает конкретную изготовленную партию заготовок с фиксацией даты и количества банок.
* **Атрибуты объекта:**
  * `id: int` — уникальный идентификатор партии;
  * `preserve: Preserve` — ссылка на объект заготовки;
  * `production_date: str` — дата изготовления (в формате `ГГГГ-ММ-ДД`);
  * `quantity: int` — количество банок в наличии;
  * `is_consumed: bool` — флаг полного расхода партии (`True`, если банок не осталось; аналог флага отмены бронирования из методички).
* **Методы:**
  * `__init__(self, batch_id: int, preserve: Preserve, production_date: str, quantity: int) -> None` (проверяет `quantity >= 0`, при `quantity == 0` выставляет `is_consumed = True`).
  * `__str__(self) -> str` — формат: `[Партия #1] 'Маринованные огурцы' от 2026-09-10: 8 шт. [АКТИВНА]` (или `[ИЗРАСХОДОВАНА]`).
  * `consume(self, amount: int) -> bool` — бизнес-метод списания банок. Уменьшает `self.quantity` на `amount`. Если остаток становится 0, выставляет `self.is_consumed = True`. Возвращает `False`, если запрошенное количество превышает остаток.
  * `@staticmethod validate_quantity(quantity: int) -> bool` — проверка на неотрицательное целое число.
  * `@classmethod from_data(cls, data: dict, preserve: Preserve) -> "Batch"`
  * `to_dict(self) -> dict` — сохраняет `"preserve_id": self.preserve.id`, дату, количество и флаг `is_consumed`.
* **Функции модуля `batches.py`:**
  * `create_batch(batches: list[Batch], preserve: Preserve, prod_date: str, quantity: int) -> Batch | None`
  * `find_batch_by_id(batches: list[Batch], batch_id: int) -> Batch | None`
  * `consume_from_batch(batches: list[Batch], batch_id: int, amount: int) -> bool`
  * `get_active_batches(batches: list[Batch]) -> list[Batch]` — отбор с использованием спискового включения / генератора.
  * `sort_batches_by_date(batches: list[Batch], reverse: bool = True) -> list[Batch]` — сортировка с lambda-функцией (`key=lambda b: b.production_date`).
  * `get_batch_status(batch: Batch) -> str` — функция, перешедшая из ПР1, возвращающая текстовый статус доступности партии для употребления.
  * `show_batches(batches: list[Batch]) -> None`

### 4. Модуль работы с хранилищем (`storage.py`)

Модуль обязан сохранять данные в файловой системе и связывать сущности по ID при чтении:
* **Формат файлов:**
  * `data/products.json`: список объектов с полями `id`, `name`, `category`.
  * `data/preserves.json`: список объектов с полями `id`, `name`, `product_id`, `recipe_notes`.
  * `data/batches.json`: список объектов с полями `id`, `preserve_id`, `production_date`, `quantity`, `is_consumed`.
* **Функции:**
  * `load_products(filepath: str) -> list[Product]`
  * `save_products(filepath: str, products: list[Product]) -> None`
  * `load_preserves(filepath: str, products: list[Product]) -> list[Preserve]` — находит соответствующий `Product` по `product_id` и передает в фабрику `Preserve.from_data`.
  * `save_preserves(filepath: str, preserves: list[Preserve]) -> None`
  * `load_batches(filepath: str, preserves: list[Preserve]) -> list[Batch]` — находит соответствующий `Preserve` по `preserve_id` и передает в фабрику `Batch.from_data`.
  * `save_batches(filepath: str, batches: list[Batch]) -> None`
* **Отказоустойчивость:** Все функции чтения должны обрабатывать отсутствие файла (`FileNotFoundError`) и ошибки парсинга (`json.JSONDecodeError`), возвращая пустой список `[]` без падения программы. Запись должна производиться через контекстный менеджер `with open(..., "w", encoding="utf-8") as f:`.

### 5. Модуль вспомогательных функций ввода (`utils.py`)

Обеспечивает надежный пользовательский ввод:
* `input_int(prompt: str, min_val: int | None = None, max_val: int | None = None) -> int`: запрашивает число в цикле, перехватывает `ValueError`.
* `input_date(prompt: str) -> str`: запрашивает дату и валидирует её через `datetime.date.fromisoformat()` или `strptime(..., "%Y-%m-%d")`.
* `input_str(prompt: str, min_len: int = 1) -> str`: запрашивает строку, обрезает пробелы (`strip()`), повторяет ввод, если строка короче `min_len`.

### 6. Консольный интерфейс и сценарии (`main.py`)

Главный файл организует меню с возможностью выполнения всех базовых действий:

```text
=== Система учета домашних заготовок ===
1. Показать список партий в погребе
2. Показать виды заготовок и продукты
3. Добавить новый исходный продукт
4. Добавить рецепт/вид заготовки
5. Зарегистрировать изготовленную партию (дата, количество)
6. Списать/израсходовать банки из партии
7. Поиск заготовок по названию
8. Сортировка партий по дате изготовления
9. Сохранить изменения
0. Выход из программы
```

* При старте вызываются функции загрузки данных из `storage.py`.
* При штатном выходе (пункт `0`) происходит автосохранение всех коллекций.
* Точка входа оформлена строго через `if __name__ == "__main__": main()`.

### 7. Модульные тесты (`tests/`)

Необходимо реализовать не менее 6–8 подробных тестов для проверки ООП-логики:
1. `tests/test_products.py`:
   * Создание экземпляра `Product`, проверка атрибутов и метода `__str__`.
   * Работа статического метода `validate_name`.
   * Поиск продуктов по имени.
2. `tests/test_preserves.py`:
   * Создание `Preserve`, проверка связи с объектом `Product`.
   * Корректная генерация словаря через `to_dict()`.
3. `tests/test_batches.py`:
   * Создание `Batch`, проверка наличия ссылок на `Preserve` и `Product`.
   * Успешное списание части банок методом `consume()`.
   * Полное списание банок с переключением `is_consumed = True`.
   * Отказ при попытке списать больше банок, чем имеется в наличии.
   * Сортировка партий по дате с использованием lambda-функции.

Запуск тестов должен осуществляться штатной командой:
```bash
pytest -v
```
Все тесты должны завершаться со статусом `PASSED`.

* Все сигнатуры функций и методов обязаны содержать **аннотации типов** (`type hints`).
* Все классы, методы и функции должны иметь осмысленные **docstrings** на русском языке.
* Полное соблюдение стандарта **PEP 8**:
  * Длина строки не более 79–88 символов;
  * Отсутствие неиспользуемых импортов и переменных;
  * Корректные отступы (4 пробела), две пустые строки между определениями верхнего уровня.
* Команда проверки не должна возвращать ошибок:
```bash
flake8 .
```
