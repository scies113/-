# Система учета домашних заготовок

Проект ведёт каталог сырья и рецептов, показывает партии банок и остатки в погребе. Веб-интерфейс использует Python 3.10+, Django 5.2, Django ORM, SQLite 3.31+ и шаблоны Django с Bootstrap. Данные можно менять через формы сайта и Django Admin. Консольное приложение из ПР1–ПР3 хранит данные в JSON и запускается отдельно.

## Запуск веб-приложения

```powershell
git clone https://github.com/scies113/-.git home_preserves
cd home_preserves
git switch pr9-django-orm
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

python manage.py import_pr7

```

Откройте [главную страницу](http://127.0.0.1:8000/) или войдите в [админку](http://127.0.0.1:8000/admin/) под созданной учётной записью. При обновлении заполненной базы установите зависимости и примените новые миграции. Суперпользователя достаточно создать один раз. На Linux и macOS окружение активируется командой `source venv/bin/activate`.

## База данных и перенос из ПР7

Django создаёт таблицы в локальном файле `db.sqlite3`. Миграции лежат в `preserves/migrations/` и `batches/migrations/`. По умолчанию команда `import_pr7` читает исходный файл `data/preserves.sqlite` в режиме только для чтения. Чтобы загрузить другую копию базы ПР7, передайте её путь:

```powershell
python manage.py import_pr7 "C:\путь\к\preserves.sqlite"
```

Импорт переносит записи в порядке «сырьё → заготовки → партии» с сохранением ID, внешних ключей, дат и количества. Флаг `is_consumed` преобразуется в `consumed` для израсходованных партий и `active` для остальных. Повторный запуск пропускает совпадающие записи. При конфликте ID с изменённой записью или нарушении ограничений импорт откатывается целиком.

Миграция `batches.0003_batch_status` так же преобразует уже загруженные записи ПР9. По завершении остаётся поле `status`. При возврате к схеме ПР9 оба неактивных статуса сводятся к флагу `is_consumed=True`. Миграция `preserves.0003_preserve_slug` заполняет уникальные слаги на основе названия и ID, поэтому одноимённые рецепты сохраняют разные адреса.

В ПР11 миграция `batches.0004_unique_active_slot` устанавливает ограничение одной активной партии для заготовки на одну дату. Если в другой базе уже есть такие дубли, миграция останавливается и сохраняет все записи. Сначала разрешите конфликт в базе ПР10. Миграция `preserves.0004_preserve_photo` добавляет необязательное поле фотографии. Существующие заготовки открываются без изображения.

| Модель | Поля помимо ID | Связь |
| --- | --- | --- |
| `Product` | `name`, `category` | `product.preserves` возвращает рецепты |
| `Preserve` | `name`, `product`, `recipe_notes`, `slug`, `photo` | `ForeignKey` на `Product`; `preserve.batches` возвращает партии |
| `Batch` | `preserve`, `production_date`, `quantity`, `status`, `available_quantity` | `ForeignKey` на `Preserve` |

Для первичных ключей используется `BigAutoField`. У обеих связей задано `on_delete=RESTRICT`. Количество банок неотрицательное, партия по умолчанию активна, примечания к рецепту могут быть пустыми.

`Batch.Status` определяет статусы «В наличии», «Израсходована» и «Списана». Виртуальное поле `available_quantity` вычисляется SQLite через `GeneratedField`: для активной партии оно равно `quantity`, для остальных равно нулю. Количество банок в карточке сохраняется для истории, а сводка считает вычисляемый остаток.

## Страницы

| Маршрут | Назначение |
| --- | --- |
| `/` | Сводка по сырью, рецептам и остаткам, три партии с наибольшим запасом |
| `/preserves/` | Каталог с поиском по названию и фильтром наличия по дате производства |
| `/preserves/recipe/<slug>/` | Карточка заготовки со сведениями о сырье. Прежний маршрут `/preserves/<id>/` тоже работает |
| `/preserves/products/` | Справочник сырья с количеством рецептов |
| `/batches/` | Активные партии, по пять на страницу |
| `/batches/<id>/` | Карточка партии и ссылка на её рецепт |
| `/batches/search/` | Поиск по названию заготовки или сырья, фильтры по дате, статусу, заготовке, сырью и категории, сортировка и пагинация |
| `/batches/statistics/` | Количество партий по статусам, остатки банок и группировка по заготовкам |
| `/batches/new/`, `/batches/<id>/edit/` | Создание и редактирование активной партии |
| `/batches/<id>/discard/` | Подтверждённое списание через POST |
| `/preserves/new/`, `/preserves/<id>/edit/` | Создание и редактирование заготовки с фотографией |
| `/admin/` | Управление сырьём, заготовками и партиями |

Поиск по названиям работает без учёта регистра, в том числе на кириллице. Параметры поиска партий можно комбинировать. Например, `/batches/search/?date=2026-10-22&status=active&sort=quantity` показывает активные партии на указанную дату по убыванию остатка. Ссылки пагинации сохраняют параметры. Для ошибочных фильтров появляется сообщение. Неизвестный режим сортировки заменяется сортировкой по дате от новых партий. В каталоге фильтр даты показывает рецепты, у которых есть активная партия с положительным остатком и указанной датой производства.

## Формы и фотографии

- После входа в админку откройте обычный список партий или каталог заготовок. Кнопки добавления и редактирования видны пользователям с соответствующими правами Django.
- `BatchFilterForm` проверяет GET-параметры. При несовпадении сырья с выбранной заготовкой форма показывает общую ошибку.
- `BatchForm` принимает заготовку, дату и положительное количество. Дата новой или перенесённой партии не может быть в прошлом. У существующей активной партии с прошедшей датой можно уточнить количество, сохранив её дату и заготовку.
- Для списания раскройте «Списать» и подтвердите действие. Партия сохраняется со статусом «Списана», исчезает из активного списка и освобождает пару «заготовка + дата» для новой записи.
- `PreserveForm` принимает необязательную фотографию JPEG, PNG или WebP до 5 МБ и до 4096 пикселей по каждой стороне. Её можно загрузить, заменить или убрать из карточки. В админке действуют те же проверки.
- Загруженные файлы хранятся в `media/preserves/`. Django записывает путь к файлу в SQLite и раздаёт его по `/media/` при локальном запуске с `DEBUG=True`.

## Административная панель

- В справочнике сырья можно искать по названию и категории, фильтровать по категории и редактировать связанные заготовки в карточке продукта.
- В списке заготовок можно искать по названию и сырью. В карточке видны связанные партии. Ссылка «Посмотреть на сайте» ведёт на страницу с уникальным слагом.
- В списке партий отображаются заготовка, сырьё, дата, количество, статус и вычисляемый остаток. Поиск работает по названиям заготовки и сырья. Доступны фильтры по статусу, дате и сырью, а также выбор периода по дате производства. После изменения статуса публичный каталог и статистика используют новый остаток.

### Где посмотреть ORM-запросы

- `homepage/views.py` считает рецепты и продукты, суммирует активные остатки и ограничивает выдачу трёх крупнейших партий срезом.
- `preserves/views.py` использует `Exists` для проверки наличия, `get_object_or_404()` для карточки и `Count()` для подсчёта рецептов каждого продукта.
- `batches/models.py` содержит `BatchQuerySet` с методами `active()`, `available()`, `with_details()` и `search()`. `batches/views.py` объединяет фильтры и поиск через `Q`, выбирает нужные поля с помощью `values()` и `F()` и передаёт выборку в `Paginator`. Статистика использует `aggregate()` и `annotate()`. Заготовки без партий отображаются с нулевыми значениями.

### Анализ SQL через Django Debug Toolbar

Для анализа запросов включите панель и запустите сервер разработки на loopback:

```powershell
$env:DJANGO_DEBUG_TOOLBAR = "1"
python manage.py runserver 127.0.0.1:8000
```

Откройте нужную страницу на `127.0.0.1:8000` и выберите вкладку SQL. У анонимного запроса к карточке партии выполняется один запрос с соединением таблиц заготовок и сырья. Список активных партий выполняет два запроса: подсчёт и выборку текущей страницы. На странице поиска добавляются два запроса для списков выбора сырья и заготовок. Переход на вторую страницу использует `LIMIT` и `OFFSET`. Панель выключена при обычном запуске и во встроенном тестовом раннере.

### Проверка CRUD в Django shell

Команды создают и удаляют отдельную учебную запись.

```python
# python manage.py shell
from preserves.models import Product

demo = Product.objects.create(name="Пробная запись", category="овощи")
Product.objects.get(pk=demo.pk).name
demo.name = "Обновлённая пробная запись"
demo.save(update_fields=["name"])
demo.refresh_from_db()
demo.name
demo.delete()
```

## Структура проекта

- `config/` содержит настройки и корневые маршруты Django.
- `homepage/`, `preserves/` и `batches/` содержат представления, маршруты и шаблоны. Модели размещены в приложениях `preserves` и `batches`.
- `preserves/management/commands/import_pr7.py` читает исходную базу и записывает данные через ORM.
- `templates/` и `static/` содержат общие шаблоны, стили и скрипты.
- `main.py`, `models/`, `storage.py` и `data/*.json` обслуживают консольную версию. Запуск — `python main.py`.
- `db/` и `sql/` содержат материалы ПР7 и прежний скрипт импорта JSON в исходную базу.
