# Система учета домашних заготовок

Веб-приложение и консольная система на языке Python для автоматизации учета заготовок, базового сырья, партий консервации и контроля остатков банок в погребе или кладовой (Практические работы № 1 – № 7).

---

## 1. Назначение и предметная область

### Назначение
Программа предназначена для:
* Ведения каталога исходного сырья (продуктов);
* Учета рецептур и видов домашних заготовок;
* Регистрации изготовленных партий с указанием даты выработки и количества банок;
* Контроля расхода и списания банок из конкретных партий;
* Быстрого поиска заготовок, фильтрации по дате/статусу и анализа запасов.

### Целевая аудитория
* Домохозяйства и семьи, заготавливающие консервацию на зиму;
* Владельцы приусадебных участков, дачники и садоводы;
* Любители домашнего консервирования, солений, джемов и сушеных запасов.

### Предметная область
Предметная область описывает жизненный цикл домашней консервации:
```text
[ Исходный продукт (сырье) ]
            │
            ▼ (основа рецепта)
    [ Вид заготовки ]
            │
            ▼ (изготовление в определенный день)
    [ Партия банок (дата, количество) ]
            │
            ▼ (потребление/списание)
    [ Учет остатков и статуса ]
```

## 3. Веб-интерфейс (Django 5.2)

Веб-приложение построено на фреймворке **Django 5.2** с разделением ответственности по трем приложениям:

### Таблица маршрутов системы

| URL | Пространство имен:Имя | Представление | Описание |
| :--- | :--- | :--- | :--- |
| `/` | `homepage:index` | `homepage.views.index` | Главная страница системы, визитная карточка с агрегированной сводкой и быстрым переходом. |
| `/preserves/` | `preserves:list` | `preserves.views.preserve_list` | Каталог всех видов заготовок с привязкой к сырью. |
| `/preserves/<int:preserve_id>/` | `preserves:detail` | `preserves.views.preserve_detail` | Подробная карточка заготовки (возвращает 404, если объект не найден). |
| `/preserves/products/` | `preserves:products` | `preserves.views.product_list` | Справочник сырья с категориями и числом связанных рецептур. |
| `/batches/` | `batches:list` | `batches.views.batch_list` | Список активных партий в погребе с датами и остатками. |
| `/batches/<int:batch_id>/` | `batches:detail` | `batches.views.batch_detail` | Карточка конкретной партии с сырьем и статусом (404, если не найдена). |
| `/batches/search/` | `batches:search` | `batches.views.batch_search` | Форма поиска и фильтрации партий по дате выработки и статусу. |
| `/batches/statistics/` | `batches:statistics` | `batches.views.batch_statistics` | Аналитическая панель: остатки банок, группировка по видам заготовок. |

Корневая маршрутизация настроена в `config/urls.py` через `include()`. Обработка несуществующих страниц переопределена через `handler404 = 'config.urls.custom_page_not_found'` с возвратом статуса `404 Not Found`.

Во всех представлениях реализованы строгие аннотации типов аргумента `request` (`HttpRequest`).

## 4. Шаблонизация и статические файлы (DTL)

Интерфейс использует **Django Template Language (DTL)** без формирования HTML-строк внутри контроллеров `views.py`.

* **Иерархия шаблонов:**
  * `templates/base.html`: главный каркас приложения, мета-теги, адаптивная сетка Bootstrap 5.3 (через CDN), блоки `{% block title %}` и `{% block content %}`;
  * `templates/includes/navigation.html`: меню навигации, где все ссылки формируются строго через тег `{% url 'namespace:name' %}`;
  * `templates/includes/batch_status.html`: переиспользуемый микро-шаблон цветовой индикации статуса партии (`{% if batch.is_consumed %}`);
  * `templates/404.html`: стилизованная страница ошибки отсутствия страницы или ресурса.
* **Использование возможностей DTL:**
  * Циклы `{% for ... in ... %}` с обязательной обработкой пустых наборов через блок `{% empty %}`;
  * Фильтры: `|length` для подсчета элементов, `|default:"Нет данных"` для безопасного вывода пустых значений, `|date:"d.m.Y"` для форматирования календарных дат.
* **Статические файлы (`static/`):**
  * `static/css/style.css`: уникальные стили карточек `.preserve-card`, фирменная цветовая гамма, эффекты наведения и оформление бейджей;
  * `static/js/main.js`: клиентский сценарий автоматической актуализации года в футере;
  * `static/img/logo.png`: фирменный логотип в шапке сайта.

## 5. База данных и сырые SQL-запросы (SQLite)

> **Внимание:** В соответствии с требованиями учебной программы Django ORM (`models.Model`) не используется. Взаимодействие с базой данных реализовано через стандартную библиотеку `sqlite3` с сырыми параметризованными SQL-запросами.

### 5.1. Схема базы данных (`sql/schema.sql`)
Таблицы повторяют предметную область:
1. `products`: `id` (PK AUTOINCREMENT), `name` (TEXT NOT NULL), `category` (TEXT NOT NULL);
2. `preserves`: `id` (PK AUTOINCREMENT), `name` (TEXT NOT NULL), `product_id` (INTEGER NOT NULL FK `REFERENCES products(id)`), `recipe_notes` (TEXT NOT NULL);
3. `batches`: `id` (PK AUTOINCREMENT), `preserve_id` (INTEGER NOT NULL FK `REFERENCES preserves(id)`), `production_date` (TEXT NOT NULL), `quantity` (INTEGER NOT NULL CHECK >= 0), `is_consumed` (INTEGER NOT NULL CHECK 0/1).

В схеме включена поддержка `PRAGMA foreign_keys = ON;` и ограничений целостности `NOT NULL`, `CHECK`, `REFERENCES`.

### 5.2. Модуль подключения (`db/database.py`)
Предоставляет функцию `get_connection()`, которая:
* Создает подключение к `data/preserves.sqlite`;
* Устанавливает `conn.row_factory = sqlite3.Row` для обращения к полям строк по именам;
* Гарантированно включает `PRAGMA foreign_keys = ON;`.

### 5.3. Скрипт импорта данных (`db/import_json.py`)
Скрипт переносит данные из файлов `data/*.json` в базу данных SQLite:
* Применяет DDL-схему `sql/schema.sql`;
* Выполняет пакетную вставку методом `executemany` с плейсхолдерами `?` для безопасной параметризации.

Инициализация базы данных:
```bash
python -m db.import_json
```

### 5.4. Библиотека SQL-запросов (`sql/queries.sql`)
Файл содержит 12 документированных запросов, демонстрирующих ключевые конструкции SQL:
* Выборка активных партий (`is_consumed = 0`);
* Детальная карточка партии через двойной `JOIN` (`batches` &rarr; `preserves` &rarr; `products`);
* Агрегация: `COUNT(id)`, `SUM(quantity)`;
* Группировка `GROUP BY` запасов по заготовкам;
* Фильтрация агрегатов `HAVING COUNT(b.id) > 2`;
* Подзапросы `NOT IN` для поиска заготовок без активных партий в погребе;
* Параметризованный поиск по дате и статусу;
* Анализ истории списания израсходованных партий (`is_consumed = 1`);
* Выборка по категории сырья и топ-рейтинг заготовок по общему числу банок (`ORDER BY ... LIMIT`).

### 5.5. Безопасность SQL
Во всех `views.py` параметры из `request.GET` и URL передаются в методы `cursor.execute(sql, params)` строго через кортежи/списки параметров `?`. Конкатенация строк и f-строки для формирования SQL категорически исключены для защиты от SQL-инъекций.

## 6. Установка и запуск

### Требования
* Python 3.10 или выше;
* Установленные зависимости из `requirements.txt`.

### Установка зависимостей
```bash
pip install -r requirements.txt
```

### Инициализация базы данных SQLite
```bash
python -m db.import_json
```

### Запуск веб-приложения Django
```bash
python manage.py runserver
```
Веб-интерфейс доступен в браузере по адресу: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

### Запуск интерактивного консольного приложения (ПР1–ПР3)
```bash
python main.py
```
